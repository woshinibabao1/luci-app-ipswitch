# ADR 0002：以模组侧状态判定「切换完成」

- 状态：**已采纳**
- 日期：定案于项目初版（v1.0.0）

## 背景

调用方（zgyd）把「响应流里出现标记文本」当成切换成功的**唯一依据**，
所以本服务必须在「真的换完了」的那一刻才吐标记。于是要先定义：
**什么叫做换完了？**

## 选项

**A. 固定等 N 秒**
- 优点：实现最简单，无任何依赖
- 缺点：网络快则白等，网络慢则假成功 —— 而假成功是最坏的失败模式
  （调用方以为换了 IP，实际没换，后续请求仍打在被限流的出口上）

**B. 轮询外网 IP**
- 优点：语义最直接，「IP 变了就是变了」
- 缺点：引入外网依赖（要能访问某个 IP 查询服务），在网络本来就不稳的时刻
  去查一个外网服务，多一个失败点；还需要外网服务的可用性假设

**C. 轮询设备侧状态**
- 优点：只依赖本地设备，无外网依赖
- 缺点：要知道「什么状态才算真的好了」，判据选错会假成功

**D.（推荐口径）设备侧双条件 + 主动 renew** ← 本方案

## 决策

选 **D**，实现为 `switcher.rs` 的 `confirm_ready()`：**两个条件同时满足**才算好：

1. 模组回 `^NDISSTATQRY: 1,…`（= PDP 已连接）
   —— 这条判据与 MT5700 Console 的 `dial.js:146` 用的完全一致，不另立标准
2. WAN 接口（`MT5700M`）真的有一个 IPv4 地址

**为什么必须两个**：

- 只看 ①：模组连上了，但 DHCP 还没跑完，接口上可能还没有地址 → 上层转发还没通
- 只看 ②：**这是真机踩过的坑** —— DHCP 租约可以长达 6 天，PDP 断了 netifd 不一定会
  重跑 DHCP，接口上会**残留上一次的地址**。此时「有地址」是假象，实际已经断了。
  （`root/etc/hotplug.d/net/99-mt5700-renew` 这个钩子的全部理由，就是这个坑。）

所以切换流程在「模组已连接」之后还要**主动续约一次接口**：

```rust
// 优先走 ubus（不碰 ifdown/ifup 的完整状态机，代价最小）
ubus -S call network.interface.MT5700M renew
// 失败才回退
ifdown MT5700M && ifup MT5700M
```

生效方式会记进报告与 `/status` 的 `renewed_by`（`"ubus"` / `"ifdown-ifup"`）。

**附加的诚实标记**：切换过程中会观察链路是否真的中断过（`saw_link_down`）。
若整轮都没观察到中断，成功信息里会附上「注意：未观察到链路中断」。
这**不改变成功/失败判定**，只是一个给人和日志的线索 —— 因为「没断过」通常意味着
刚才那次 `AT^SETAUTODIAL=0` 实际没生效，IP 大概率没变。

## 后果

- ✅ 无外网依赖；调用方不需要额外配置
- ✅ 判据与 MT5700 Console 保持同一套，避免「同一台设备两套标准打架」
- ⚠️ 极端情况：DHCP 重新分配到了**同一个**地址时，本服务会判成功。
  这是刻意的取舍 —— 模组确实断开重连过，只是运营商给了同一个 IP。
  真要区分只能上选项 B（外网校验），而 B 的代价更大。`saw_link_down` 可作辅助判据
- ⚠️ `parse_ndis_active()` 严格区分 `None`（读不出来）与 `Some(false)`（未连接）：
  把「读不出来」当成「未连接」，会让我们**永远等不到成功**；
  当成「已连接」，会让我们**假成功**
